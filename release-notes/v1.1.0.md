The first packaged release. Until now the only way to run this was to clone the
repo and build it; this is a zip you can load without a Node toolchain.

## What it is

A password manager with one unusual promise: **you will actually remember your
master passphrase** — a long, randomly generated, genuinely strong one — without
writing it down. It teaches you the phrase using the method of loci, hiding each
word at a fixed spot along a route through an illustrated house, and then makes
you walk that route forward, backward and out of order before it will seal
anything.

Underneath: Argon2id (256 MiB, t=3) stretches the phrase into an AES-256-GCM
key, and the vault lives encrypted in the extension's own IndexedDB. No server,
no analytics, zero network requests. On a login page, the toolbar popup unlocks,
puts the entry for *that* site at the top, and types it straight into the form —
it never touches the clipboard.

It asks for four permissions: `activeTab`, `scripting`, `storage`, `alarms`. Not
"read and change all your data on every website".

## Install

1. Download `wherewasmypassword-1.1.0.zip` below and check it (see the checksum).
2. Unzip it.
3. Open `chrome://extensions` or `edge://extensions`, turn on **Developer mode**.
4. **Load unpacked** → select the unzipped folder.
5. Click the toolbar button, then "Memory house" — that is where you build the
   vault the first time. Set aside about ten minutes; the training is the point.

## Checksum

```
b3561d88cf337782915e74914fbc664b0c5aeb27a09947d65bddd05ee12744dd  wherewasmypassword-1.1.0.zip
```

That hash tells you the file you downloaded is the file we uploaded. It is not,
for this release, a proof of what went into it.

**What this note corrects.** These notes originally said you could check out the
`v1.1.0` tag, run `npm run package`, and get a byte-identical archive with that
same SHA-256. You cannot, and you could not on the day it was published. The zip
was built from a working tree carrying whatever line endings this machine
happened to have, and `public/` is copied into the package byte for byte — so
`background.js`, `content.js`, `manifest.json` and `popup.html` ship here with
LF, while a fresh checkout on Windows turns them into CRLF and produces a
completely different hash. (On macOS or Linux those four match and `index.html`,
which shipped mostly CRLF, is the one that does not — no platform reproduces
this archive.) Every bundled asset is byte-identical either way: what differs is
invisible characters and nothing else. Nothing about what the extension does is
in question, and the archive has not been touched since it was published.

**It is fixed from here on.** Line endings are now pinned in the repository, so
what ships is decided by the checkout rather than by whatever git config the
person building it happened to have, and the next release will be reproducible
from its tag on Windows, macOS and Linux alike. This archive was left exactly as
published rather than quietly re-cut: nothing about it is unsafe, and replacing
a download to make an old sentence true would break the hash for anyone who
already wrote it down. Correcting the sentence is the honest half of that trade.

If you want to verify v1.1.0 rather than trust it: check out the tag, build it
yourself, and load `dist/` as the unpacked extension. That is the same code, and
it does not depend on this file at all.

## Three things to know before you trust it with anything

**It does not auto-update.** A loaded zip stays exactly as it is until you
download a newer one and load that yourself. Not being on the Chrome Web Store
is a deliberate choice rather than an oversight: a store listing means
auto-update, and "whatever is signed and pushed reaches every installed vault
silently" is a decision worth taking on its own rather than as a side effect of
wanting an install link. It is deferred, not declined.

**The vault is local to the browser profile you create it in.** Nothing syncs.
Export an encrypted backup from Housekeeping and keep it somewhere off this
machine — that file plus your passphrase is the only way the vault survives a
dead disk.

**If you forget the phrase, nothing can recover the vault.** There is no reset,
no recovery email, no support address that can help. That is the deal, and it is
the entire reason the app makes you earn the phrase before it seals anything.

## What has been checked

`npm test` (272 unit and component tests), a screenshot pass over every
onboarding screen, an autofill suite that drives the packed extension in a real
browser (42 checks), and an end-to-end journey that builds a vault from the
welcome screen, stores a credential, fills it into a real login form from the
real popup, exports a backup, restores it, undoes the restore and changes the
master passphrase (35 checks). The zip in this release was also unpacked and
loaded as an extension before publishing.

The README's security model is worth reading before you rely on this. It is
candid about what this design cannot do — vault-record rollback, the clipboard
fallback, and why the hosted build is meaningfully weaker than the extension.
